ProPresenter to Lightkey

How a slide or a moment in a video on the ProPresenter PC fires a lighting cue in Lightkey on the MacBook. It’s set up once; after that the lights follow ProPresenter by themselves.

Windows PC

ProPresenter

A slide, or a point on a video’s timeline, sends a MIDI note.

→
Network

rtpMIDI ↔ Network MIDI

rtpMIDI on the PC and the Mac’s built-in Network MIDI speak the same language (RTP-MIDI).

→
MacBook

Lightkey

Each note is a trigger on a cue, which sends the look to the lights over DMX.

What to install: only rtpMIDI (free), on the Windows PC. The Mac needs nothing: its Network MIDI is the same thing, built into Audio MIDI Setup. Name the session ProPresenter Link on both machines so it’s easy to recognise everywhere it appears.

1

Open the door on the MacBook

MacBook

  1. Open Audio MIDI Setup (Applications → Utilities, or Spotlight), then Window → Show MIDI Studio, then the globe button, MIDI Network Setup.

  2. Under My Sessions, click +, rename it “ProPresenter Link”, and tick Enabled. Leave the port at 5004.

  3. Set “Who may connect to me” to Anyone. The PC makes the connection, so the Mac only has to accept it.

  4. Give the MacBook a fixed address on the network. A DHCP reservation on the router is simplest. The PC normally finds the Mac by name (Bonjour), but a fixed IP means you can add it by hand if that ever fails.

  5. If macOS asks whether to accept incoming network connections, click Allow. That appears only when the Mac’s firewall is on.

2

Connect from the PC with rtpMIDI

Windows PC

  1. Install rtpMIDI from tobias-erichsen.de. It needs Apple’s Bonjour service; if it’s missing, the installer says so and links to Apple’s download. rtpMIDI runs as a Windows service, so it starts with Windows on its own.

  2. Open rtpMIDI, click + under My Sessions, name it “ProPresenter Link”, and tick Enabled. That session name is what ProPresenter lists as a MIDI port.

  3. Under Directory, pick the MacBook and click Connect. It moves into Participants. Not listed? Click + under Directory and enter the Mac’s IP address and port 5004.

  4. When Windows Firewall asks, allow rtpMIDI on private networks. It uses UDP ports 5004 and 5005.

  5. Use wired Ethernet for both machines if you can. Wi-Fi works, but can delay or drop a note, and a dropped note is a cue that doesn’t fire.

3

Send notes from ProPresenter

Windows PC

  1. Set up rtpMIDI first, then restart ProPresenter. ProPresenter only sees MIDI ports that existed when it opened.

  2. Settings → Devices → + → MIDI. Name it “Lightkey”, turn on Auto Reconnect, and choose “ProPresenter Link” as the Destination. Destinations are where ProPresenter sends; Sources would be for controlling ProPresenter, which isn’t needed here. Click Connect.

  3. On a slide: right-click → Add Action → Communication → MIDI → MIDI Note On. Choose channel 16, a note number, and a velocity above 0. The note fires when the slide is triggered.

  4. For moments inside a video, use the presentation’s Timeline. Open it with the Timeline button at the top right of the presentation. Put the video on it, then drop the MIDI actions (or macros holding them) at the moments you want. Rewind and press Play: the video and the cues run together. The Timeline can also follow SMPTE timecode for frame accuracy.

  5. Use macros for looks you reuse. A macro called “Lights: Walk-in” holding the MIDI action can go on any slide or timeline, so the note number is set in one place.

Why channel 16: the v33 show already uses MIDI channels 1 to 4 for the Stream Deck, 230 notes in all. Keeping ProPresenter on channel 16 means a ProPresenter note can never fire a Stream Deck cue by accident. Some apps count channels 0–15, so Lightkey may show it as 15 or 16; either is the same channel.

4

Catch the notes in Lightkey

MacBook

  1. Right-click the cue → External Control → Add Trigger, then fire the ProPresenter action once. Lightkey learns the note and channel from what it receives.

  2. Change the trigger’s behaviour from Toggle to Activate. With Toggle, the same note arriving twice, as it will when you rehearse the video, switches the cue off again. Activate only ever switches it on.

  3. Save the show, and write each note down in the cue plan below. The Stream Deck and ProPresenter can both drive the same cue; whichever was pressed last wins.

Test it before a service

  1. Restart both machines and check Audio MIDI Setup on the Mac lists the PC under Participants.

  2. Play the video from the start and watch each cue come on at its moment.

  3. Play it a second time. Nothing should switch off: that proves every trigger is set to Activate.

Every week

Before the service, glance at rtpMIDI on the PC: the MacBook should be under Participants. Apple’s Network MIDI sometimes comes back after a restart enabled but not connected; if the Mac isn’t there, select it under Directory and click Connect. Booth Check keeps the MacBook awake, so the link doesn’t drop mid-service.

If a cue doesn’t fire

“ProPresenter Link” isn’t in ProPresenter’s list.

Check the session is enabled in rtpMIDI, then quit and reopen ProPresenter. It only sees ports that existed when it opened.

The Mac isn’t in rtpMIDI’s Directory.

Add it by hand with + (its IP and port 5004). Check both are on the same network, the Mac session is enabled with “Anyone”, and Bonjour is installed on the PC.

Connected, but Lightkey doesn’t react.

In Lightkey’s MIDI settings, make sure “ProPresenter Link” is listed and switched on as an input. Then check the trigger’s channel and note match what ProPresenter sends, and that the velocity isn’t 0 (a Note On at 0 counts as a Note Off).

The cue comes on, then goes off the next time.

The trigger is still on Toggle. Change it to Activate (step 4b).

It worked last week, now nothing.

One machine restarted and the session didn’t reconnect. In rtpMIDI, select the Mac under Directory and click Connect. If this keeps happening, Bome Network (paid) is a more robust alternative that reconnects by itself.
